# GitHub 开源后台项目搜索标准

## 目标

寻找一个成熟的 B 端运营管理后台基础项目，作为「过级搭子运营管理后台」MVP 的工程底座。

重点不是寻找学习类产品，而是寻找权限、列表、表单、审核、日志和数据看板能力成熟的后台框架。

## 必须能力

- 登录、路由、侧边栏、顶部栏、列表、详情、表单、分页、筛选、空状态、错误状态完整。
- 支持或易扩展 RBAC：菜单权限、按钮权限、路由守卫、页面级权限。
- CRUD 能力强，适合承接题库、题组、每日一句、外刊、写译题目和模考试卷。
- 容易新增统一审核发布状态：草稿、待审核、已通过、待发布、已发布、已下架、已回滚。
- 能扩展操作日志、权限变更日志、登录日志和敏感访问日志。
- 有图表能力，能承接基础聚合数据看板。
- TypeScript 优先，代码结构清楚，本地启动成本低，许可证允许二次开发。

## 排除标准

- 不选学生学习端、课程商城、教师班级管理、多租户学校 SaaS。
- 不选纯 UI 静态模板或无法表达权限和 mock/API 的项目。
- 不选多年未维护、构建困难、依赖严重过期的项目。
- 不选默认包含订单、支付、会员、发票、复杂 CRM、真人批改派单的大平台。
- 不选必须连接真实商业云服务、真实后端或私有服务才能启动的项目。
- 不选示例代码或文档中写入真实 token、密钥、账号凭据的项目。

## 评分规则

- 20 分：权限系统成熟，支持角色、菜单、按钮、路由守卫。
- 15 分：CRUD、表格、表单、详情、筛选、分页完善。
- 15 分：代码质量好，TypeScript、目录清晰、易扩展。
- 10 分：审核流、工作流、状态流或任务中心可复用。
- 10 分：日志、审计、登录安全或操作记录可复用。
- 10 分：图表和数据看板基础成熟。
- 10 分：本地启动简单，依赖稳定，文档清楚。
- 5 分：UI 风格适合内部运营后台，克制、清晰、高密度。
- 5 分：许可证允许二次开发和内部使用。

70 分以上进入候选；最终选择 1 个主项目，最多保留 1 个备选。
