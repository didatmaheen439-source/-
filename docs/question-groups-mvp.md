# 题组管理 Mock MVP

## 核心业务约束

- 一个题组只属于一个考试类型和一个学习模块。
- 适用人群使用固定多选标签：基础巩固、专项提升、冲刺练习。
- 题组成员只能来自已发布题目，且题目考试类型、学习模块必须与题组一致。
- 同一题目不能在一个题组内重复，题目顺序是正式业务数据。
- 草稿和已驳回题组可编辑；提交审核后由统一审核发布中心继续流转。

## 核心任务流

1. 教研人员新建题组，填写考试类型、学习模块、适用人群和预计用时。
2. 从兼容的已发布题目中多选成员，并通过上移、下移完成顺序编排。
3. 保存草稿时生成题目版本快照；提交审核时重新校验重复项、状态、考试类型和学习模块。
4. 审核中心完成审核、待发布和发布状态流转；发布动作前再次执行题组校验。
5. 已发布且校验通过的题组可被学习路径引用。
6. 模考试卷选择题组后按顺序展开为独立题目快照，每题保留来源题组 ID、名称和版本。
7. 题组详情聚合学习路径与模考试卷引用，运营人员可在下架前确认影响范围。

## 权限

- `super_admin`、`teaching_reviewer`：新建、编辑、复制、校验、提交审核。
- 具备内容读取权限的角色：查看列表、详情、版本、操作记录和引用影响。
- 审核通过、发布、下架继续服从审核发布中心的权限与自审隔离规则。

## Mock 边界

- 数据保存在开发服务器内存中，重启后恢复种子数据。
- 不接真实后端、用户数据、文件服务或真实考试系统。
- 下架前展示影响范围，但本阶段不自动级联修改学习路径或模考试卷。
