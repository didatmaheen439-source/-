# 后端核心数据模型基线

日期：2026-07-09

## 目标

本文档把当前 mock MVP 中已经跑通的核心对象整理为真实后端的首批模型基线。字段以当前实现为准，后端可按数据库范式拆表，但必须保留状态、版本、审计和敏感字段边界。

## 通用字段

所有可审核发布对象建议保留：

| 字段 | 要求 |
| --- | --- |
| `id` | 全局唯一业务 ID，前端用于路由和引用 |
| `status` | 统一审核发布状态或对象状态 |
| `version` | 业务版本号，用于展示和审核快照 |
| `dataVersion` | 乐观锁版本，保存和提交审核必须校验 |
| `createdBy` / `updatedBy` | 操作人账号 ID 或名称 |
| `createdAt` / `updatedAt` | 创建和更新时间 |
| `changeSummary` | 变更说明 |
| `impactScope` | 影响范围 |
| `reviewTaskId` | 当前关联审核任务 |
| `publishedVersion` | 当前线上生效版本 |
| `rollbackTargetVersion` | 可回滚版本 |
| `versionRecords` | 版本快照列表 |
| `operationRecords` | 对象级操作记录 |

## 用户模型

| 类别 | 字段 |
| --- | --- |
| 主键 | `id` |
| 展示字段 | 昵称、考试类型、目标分、考试日期、Onboarding、诊断状态、今日任务状态、最近活跃、反馈状态 |
| 持久化字段 | 用户目标、学习状态、学习记录、反馈记录、客服备注、AI 摘要索引、学习路径匹配摘要 |
| 敏感字段 | 手机号、邮箱、设备 ID、IP、反馈原文、AI 会话摘要中的敏感片段 |
| 关联 | hasMany 学习记录、反馈、客服备注、敏感访问日志、AI 摘要 |
| 后端要求 | 列表默认脱敏；完整敏感内容必须通过敏感访问授权接口返回；不提供用户级批量导出 |

当前 mock 已覆盖：列表、详情、学习记录、反馈处理、敏感访问、客服备注、AI 摘要和学习路径摘要。

### 1.1 反馈工作队列模型

| 模型 | 关键字段 | 说明 |
| --- | --- | --- |
| `FeedbackQueueItem` | 反馈 ID、用户 ID、摘要、类型、优先级、状态、关联模块、停留时长、超时标记、当前分派、版本号 | 列表摘要，不包含联系方式、反馈原文或完整 AI 会话 |
| `FeedbackAssignment` | 目标角色、负责人账号、分派人、分派原因、分派时间、转派来源 | 一条反馈同一时间只有一个当前主责人，历史分派保留 |
| `FeedbackResolution` | 结果摘要、处理说明、关联业务对象、提交人、提交时间 | 业务负责人回填，客服验收前状态为 `resolved` |
| `FeedbackTimelineEvent` | 状态、分派、转派、结果、退回、关闭、敏感访问 | 统一展示队列闭环和审计事件 |
| `FeedbackScopedUserContext` | 脱敏昵称、考试目标、学习状态、必要学习摘要、必要 AI 摘要 | 业务负责人可见的最小上下文 |

反馈队列与用户详情共用 `operationUsersData.feedbacks` 状态和版本号，不维护重复状态字段。

## 后台账号与角色模型

| 类别 | 字段 |
| --- | --- |
| 主键 | 账号 `id`、角色 `id` |
| 账号字段 | 登录账号、显示名称、角色、状态、数据范围、最近登录、创建时间、备注 |
| 角色字段 | 角色名、模块权限、动作权限、数据范围、描述 |
| 状态 | `enabled`、`disabled`、`locked` |
| 关联 | 账号 belongsTo 角色；角色 hasMany 模块权限、动作权限、数据范围 |
| 后端要求 | 唯一超级管理员保护；账号停用后会话失效；权限变化写审计 |

当前 mock 已覆盖：7 类角色、10 个模块、9 类动作权限、6 类数据范围、账号启停和审计日志展示。

### 5.1 进阶学习策略模型

| 模型 | 关键字段 | 说明 |
| --- | --- | --- |
| `AdvancedLearningStrategy` | 策略 ID、类型、名称、考试类型、模块、优先级、状态、版本、线上版本、数据版本 | 三类策略共用主体，类型为 `light_task`、`extra_practice`、`review_recommendation` |
| `StrategyTriggerGroup` | 条件关系、触发条件列表 | 支持可用时间、薄弱模块、正确率、连续错题、错因标签、距上次练习天数 |
| `StrategyReference` | 引用 ID、名称、类型、考试类型、模块、状态、可用性 | 可引用题目、题组、错因标签和模块 |
| `StrategyFallbackRule` | 是否启用、替代触发、替代目标 | 主引用不可用、主任务已完成或可用时间不足时生效 |
| `StrategyMatchRun` | Mock 用户、策略类型、命中策略、命中版本、结果引用、是否替代、执行状态 | 用于效果回流和用户详情快照 |
| `StrategyEffectSummary` | 命中、开始、完成、替换、跳过、完成率 | 从命中记录派生，不单独维护重复计数 |

后端要求：发布前复验引用和冲突；`dataVersion` 防并发覆盖；发布和回滚都维护线上版本指针；已发布策略不可直接编辑，只能复制为草稿；`ai_operator` 只拥有进阶策略写权限，不因此获得旧学习路径配置或用户列表权限。

当前 mock 已覆盖：登录、权限拒绝、提交审核、发布、下架、回滚、账号状态变更、敏感访问和反馈处理。

## 后端必须重新实现的 mock 能力

- 账号会话隔离和停用失效。
- 菜单、动作、数据范围三层权限强校验。
- 统一状态机和提交人/审核人职责分离。
- `dataVersion` 乐观锁和版本冲突。
- 审核任务和业务对象版本快照事务一致性。
- 发布前复验、下架影响范围和回滚版本校验。
- 敏感字段脱敏、访问原因和审计日志写入。
- 聚合指标和导出字段过滤。
