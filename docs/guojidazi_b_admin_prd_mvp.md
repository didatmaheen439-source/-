# 过级搭子 B 端运营管理后台 PRD（MVP）

> 文档版本：V1.0  
> 产品阶段：内部运营后台 MVP  
> 文档用途：可直接作为 Codex 的产品需求输入，用于拆分页面、数据模型、权限、接口和验收任务  
> 适用范围：过级搭子 App 配套 B 端运营管理后台

---

## 1. 项目背景

### 1.1 产品现状

过级搭子 App 已形成相对完整的用户学习闭环：

1. 用户通过登录与 Onboarding 设置考试类型、目标分数、考试日期、每日学习时长和当前学习状态。
2. 系统通过诊断识别用户薄弱模块，生成优先级和今日陪练任务。
3. 用户可完成词汇、听力、阅读、写作、翻译、模考、外刊和每日一句等学习内容。
4. 用户答错后进入 AI 讲解和错因沉淀；写作与翻译提交后进入 AI 批改和二次修改。
5. 用户可在复盘页查看错因、批改记录、学习报告和下一步建议。
6. AI 陪练承担答疑、翻译、作文与翻译建议、题目拆解、练习引导和情绪支持，并需要遵守防依赖规则。

当前用户端核心功能已可在 Mock 数据支撑下运行，但缺少统一的内部运营工具，导致以下问题：

- 题库、题组、外刊、每日一句、写译题目等内容无法集中管理。
- 诊断规则、今日任务模板和复练推荐缺少配置与版本管理。
- AI Prompt、回答结构、防依赖规则和异常回复缺少治理入口。
- 用户反馈、学习状态和必要的 AI 会话摘要缺少受控排查能力。
- 内容、题库和策略上线前缺少统一审核、发布、下架和回滚流程。
- 关键操作、敏感数据访问和权限变更缺少审计记录。
- 产品运营和学习效果缺少统一的聚合数据看板。

### 1.2 后台定位

后台名称暂定为「过级搭子运营管理后台」。

首版定位为**内部运营后台**，服务内容运营、教研、AI 策略、用户支持、数据分析、审计和系统管理人员。后台用于管理 App 已有业务，不作为新的学生学习端，也不面向学校、教师或机构开放。

### 1.3 MVP 范围原则

- 先保证业务闭环可运行，再考虑平台化和自动化。
- 先支持人工创建、编辑、审核、发布、抽检和查看数据，再考虑智能审批和复杂实验。
- 采用最小权限原则，用户明细、AI 会话和反馈原文按需展示并留痕。
- 数据看板以聚合指标为主，不建设复杂自助 BI。
- 所有影响线上用户体验的内容与策略必须可追踪版本和操作记录。

### 1.4 明确不做范围

MVP 不包含以下能力：

- 多租户学校或机构后台。
- 教师、班级、作业和学生分组。
- 课程售卖、会员套餐、订单、支付和发票。
- 复杂客服 CRM 和大型工单系统。
- 真人批改派单、质检、结算和 SLA 大系统。
- 复杂 A/B 实验平台或真实模型训练平台。
- 独立学生 Web 学习端。
- 用户级学习明细批量导出。
- 完整 AI 会话批量导出。

## 2. 后台建设目标

### 2.1 业务目标

| 目标 | 说明 | MVP 成功判断 |
| --- | --- | --- |
| 内容可管理 | 统一管理题库、题组、每日一句、外刊、写作、翻译、模考内容和素材 | 核心内容可完成创建、编辑、审核、发布、下架与版本追踪 |
| 学习路径可配置 | 管理 Onboarding、诊断、今日任务、轻量任务、追加陪练和复练推荐 | 规则可配置、可审核、可发布、可回滚 |
| AI 行为可治理 | 管理意图、Prompt、回答结构、防依赖、附件策略和会话抽检 | AI 策略变更有版本，异常回复可标记和闭环处理 |
| 用户问题可排查 | 支持客服查看用户目标、诊断、任务、练习、反馈和必要会话摘要 | 客服可定位用户问题，敏感访问全程留痕 |
| 发布过程可控 | 统一内容、题库、学习路径和 AI 策略的审核发布流程 | 不允许未审核对象直接上线，高风险动作可追溯 |
| 运营效果可观察 | 提供用户、路径、内容、题库、写译、模考、AI 和留存看板 | 数据分析可查看并导出允许范围内的聚合报表 |
| 权限与操作可审计 | 管理后台账号、角色、权限、登录和关键操作日志 | 7 类角色权限可配置，关键动作和敏感访问均有日志 |

### 2.2 用户体验目标

- 角色登录后只看到与自身职责相关的导航、页面和操作。
- 列表页采用统一的搜索、筛选、分页、状态标签和详情入口。
- 创建与编辑页面明确必填项、状态限制和提交审核条件。
- 审核、发布、下架、回滚、停用和权限变更均要求二次确认及原因。
- 无数据、无权限、加载失败、审核驳回和发布失败均有明确反馈。
- 工作台仅提供摘要和入口，不承载完整业务编辑。

### 2.3 交付目标

MVP 应交付以下最小闭环：

1. 用户查看与学习记录查询。
2. 题库、每日一句、外刊和写译题目管理。
3. 诊断规则和今日任务配置。
4. AI 陪练策略与会话抽检。
5. 内容和策略审核发布。
6. 基础运营数据看板。
7. 后台账号、角色权限和审计日志。
8. 模考内容与结果统计的基础承接。

## 3. 后台用户角色

### 3.1 角色定义

| 角色 | 角色定位 | 核心职责 | 禁止范围 |
| --- | --- | --- | --- |
| 超级管理员 | 系统级管理与风险兜底 | 管理账号、角色、权限、系统参数、审核流程、日志；处理紧急下架与回滚 | 不应常态化绕过审核直接修改业务内容；高风险操作必须说明原因 |
| 内容运营 | 运营内容维护者 | 管理每日一句、外刊、素材和基础内容；提交审核；查看内容效果 | 不审核高风险教研内容，不修改 AI 策略，不查看完整用户敏感明细 |
| 教研审核 | 题库与教学质量负责人 | 管理题目、题组、解析、错因标签、写译题目、模考试卷；执行教研审核 | 不管理账号权限，不查看完整用户隐私，不修改系统级 AI 策略 |
| AI 策略运营 | AI 陪练行为治理负责人 | 管理意图、Prompt、回答结构、防依赖、附件策略、抽检、异常回复和策略版本 | 不修改题库标准答案，不删除用户数据，不无审核发布高风险策略 |
| 用户支持/客服 | 用户问题排查与反馈处理 | 搜索用户、查看必要学习状态和会话摘要、处理反馈、添加备注 | 不修改题库、内容、路径或 AI 策略，不发布内容，不批量导出用户数据 |
| 数据分析 | 聚合指标与学习效果分析 | 查看用户、路径、内容、题库、写译、模考、AI 和留存指标；导出聚合报表 | 不修改业务数据，不查看完整会话和用户敏感明细，不导出用户明细 |
| 只读审计 | 风险与合规审计 | 查看操作日志、发布记录、权限变更、敏感访问和登录安全记录 | 不新增、编辑、审核、发布、删除、停用或导出业务数据 |

### 3.2 权限动作定义

| 标记 | 权限动作 | 产品含义 |
| --- | --- | --- |
| - | 不可访问 | 不展示菜单和按钮，直接访问地址时返回无权限 |
| R | 查看 | 查看列表、详情、状态、版本和基础记录 |
| C | 创建 | 新建草稿、账号、标签或配置 |
| E | 编辑 | 修改处于可编辑状态的对象 |
| S | 提交审核 | 将草稿提交至审核流程 |
| A | 审核 | 审核通过或驳回，并填写审核意见 |
| P | 发布类操作 | 发布、下架、回滚 |
| D | 导出 | 导出允许范围内的聚合数据 |
| X | 删除或停用 | 删除草稿、停用内容、规则或账号 |
| Config | 系统配置 | 配置角色权限、系统参数和审核流程 |

## 5. 功能模块

### 5.1 工作台

**模块目标：** 为不同角色聚合当日待办、审核任务、异常提醒、核心指标和风险摘要，作为业务入口，不承载完整编辑流程。

| 维度 | 需求 |
| --- | --- |
| 页面 | 今日待办、审核待办、异常提醒、核心指标、最近发布、风险提示 |
| 核心字段 | 待办类型、来源模块、对象名称、优先级、状态、负责人、截止时间；异常类型、严重级别、影响范围、发生时间、处理状态；指标名称、当前值、环比；版本号、对象类型、发布时间、发布人、发布结果 |
| 核心操作 | 查看个人待办；按类型和状态筛选；标记已读；跳转业务详情；查看最近发布和风险日志 |
| 权限 | 所有角色可查看与自身职责相关的摘要；只读审计只看风险和日志摘要 |
| 验收标准 | 登录后展示基于角色过滤的数据；待办可正确跳转；无权限信息不出现；异常和发布失败可被识别；摘要数据与对应模块一致 |

### 5.2 用户管理

**模块目标：** 支持客服和授权人员查询用户学习状态、排查问题、处理反馈，并保证敏感数据访问受控可追踪。

| 维度 | 需求 |
| --- | --- |
| 页面 | 用户列表、用户详情、学习记录、AI 陪练摘要、反馈记录、隐私处理记录 |
| 核心字段 | 用户 ID、昵称、考试类型、目标分、考试日期、每日学习时长、Onboarding 状态、诊断状态、薄弱模块、今日任务状态、最近活跃；学习模块、任务类型、完成状态、正确率、错因标签、耗时；反馈类型、摘要、状态、处理人、处理备注；会话时间、意图、摘要、异常标记、策略版本 |
| 核心操作 | 搜索和筛选用户；查看用户详情与学习记录；查看必要会话摘要；添加客服备注；更新反馈状态；分派关联模块；查看隐私处理和访问日志 |
| 权限 | 客服查看排查所需数据并处理反馈；数据分析仅看脱敏或聚合数据；无关角色不进入用户明细；所有敏感访问写日志 |
| 验收标准 | 可通过用户 ID、昵称等关键词定位用户；一个页面可判断 Onboarding、诊断和今日任务状态；反馈处理过程可追踪；访问日志写入失败时不得展示敏感数据 |

### 5.3 题库与内容管理

**模块目标：** 统一管理题目、题组、错因标签、每日一句、外刊和内容素材，支撑持续内容供给和审核发布。

| 维度 | 需求 |
| --- | --- |
| 页面 | 题库管理、题组管理、错因标签、每日一句、外刊内容、内容素材 |
| 核心字段 | 题目 ID、题型、考试类型、题干、选项、答案、解析、难度、错因标签、状态、版本；题组名、模块、题目清单、预计用时、适用人群；标签名、适用题型、说明、启用状态；每日一句日期、英文、译文、出处、配图、发布计划；外刊标题、分类、摘要、正文、难度、配图；素材名、类型、来源、用途、关联内容 |
| 核心操作 | 新建、编辑和复制草稿；选择题目组成题组；调整题目顺序；维护错因标签；上传和关联素材；提交审核；查看审核结果、版本、效果；申请下架或回滚 |
| 权限 | 内容运营管理每日一句、外刊和素材；教研管理并审核题目、题组、解析和标签；发布统一进入审核发布模块 |
| 验收标准 | 各内容类型均可从草稿流转至发布；必填字段缺失不可提交；已发布对象不可直接覆盖编辑；被规则引用的题目或标签在停用前展示影响范围；版本可追溯 |

### 5.4 学习路径配置

**模块目标：** 配置用户条件、诊断结果与今日任务之间的基础规则，使学习路径可管理、可审核、可回滚。

| 维度 | 需求 |
| --- | --- |
| 页面 | Onboarding 配置、诊断规则、今日任务模板、轻量任务策略、追加陪练策略、复练推荐策略 |
| 核心字段 | 选项名、字段类型、选项值、排序、启用状态；规则名、适用考试、题目范围、判定条件、输出结果、版本、状态；模板名、适用条件、任务项、题组绑定、预计分钟数；触发条件、替代规则、推荐模块、优先级、间隔规则 |

### 6.2 通用页面规范

所有列表和详情页需遵守以下规则：

- 列表支持分页、加载状态、空状态、错误状态和无权限状态。
- 搜索关键词前后空格需自动处理；筛选条件可重置。
- 状态字段统一使用状态标签，不同模块不得自行新增同义状态。
- 列表操作按钮根据权限和对象状态动态显示。
- 创建和编辑页面离开时，如有未保存内容需二次确认。
- 详情页展示创建人、创建时间、更新人、更新时间、当前版本和状态。
- 高风险操作使用确认弹窗，并要求填写原因或影响说明。
- URL 或路由直接访问仍需执行权限校验，不能仅隐藏菜单。
- 后台所有时间统一展示为系统配置时区，存储层使用统一时间标准。

## 8. 业务流程

### 8.1 内容从创建到发布

**适用对象：** 每日一句、外刊、素材关联、写作题目、翻译题目等。

1. 内容运营或教研创建草稿。
2. 填写业务字段，系统实时校验必填项和关联对象。
3. 提交审核，生成审核任务和对象版本快照。
4. 审核人查看详情、版本差异和适用场景。
5. 审核通过后进入“已通过”；驳回时必须填写原因，对象进入“已驳回”。
6. 已通过对象进入“待发布”。
7. 授权角色确认发布时间与影响范围，执行发布。
8. 发布成功后进入“已发布”；失败则保持发布前状态，不影响当前线上版本。
9. 已发布对象可按权限执行下架或回滚，并保留原因和影响记录。

**状态：** 草稿 → 待审核 → 已通过 → 待发布 → 已发布；待审核 → 已驳回 → 草稿；已发布 → 已下架或已回滚。

### 8.2 题库与模考试卷上线

1. 教研创建或编辑题目草稿。
2. 配置题型、考试类型、题干、答案、解析、难度和错因标签。
3. 通过题目校验后，将题目加入题组或试卷分区。
4. 系统校验题目状态、题组顺序、试卷分值和计时配置。
5. 教研提交审核，审核人检查题目质量、标准答案、解析和结构。
6. 审核通过后生成待发布版本。
7. 发布成功后，用户端只读取已发布版本。
8. 题目下架前检查其被题组、诊断、任务模板或试卷引用的影响。

### 8.3 学习路径规则发布与回滚

1. 教研或 AI 策略运营创建诊断、任务或推荐规则草稿。
2. 配置适用考试、触发条件、题目或题组引用、输出结果和优先级。
3. 系统执行规则完整性、引用有效性和优先级冲突校验。
4. 提交审核并生成版本快照。
5. 审核通过后进入待发布。
6. 发布时记录影响范围和生效版本。
7. 出现异常时选择历史版本执行回滚。
8. 回滚成功后历史版本重新生效，当前问题版本保留记录但不再生效。

### 8.4 AI 策略配置、抽检与异常闭环

1. AI 策略运营创建或编辑意图、Prompt、回答结构、防依赖或附件策略。
2. 系统校验策略关联关系和必填项。
3. 提交审核；高风险防依赖或回答规则必须经过审核。
4. 发布策略版本并记录变更摘要。
5. 系统生成会话摘要和策略版本关联信息。
6. AI 策略运营按条件抽检会话摘要。
7. 发现异常后标记异常类型、严重级别和处理状态。
8. 分析异常是否来源于意图、Prompt、回答结构或规则。
9. 完成策略修正并重新走审核发布；异常记录填写处理结果后关闭。

### 8.5 用户反馈处理

1. 用户反馈进入反馈工作队列，初始状态为 `pending`。
2. 客服筛选待分诊反馈，查看反馈摘要、关联模块和脱敏用户上下文。
3. 需要查看反馈原文时，客服或超管填写访问原因；敏感访问日志写入成功后才临时展示原文。
4. 客服将反馈分派给内容、教研或 AI 下的唯一有效负责人，状态变为 `processing`。
5. 负责人只能查看分派给自己的反馈和必要脱敏上下文，处理后回填结果摘要、处理说明和可选关联对象，状态变为 `resolved`。
6. 客服验收处理结果：确认后进入 `closed`；如需补充，填写退回原因并回到 `processing`。
7. 客服判断无需处理时，从 `pending` 或 `processing` 标记为 `no_action`，原因必填，再关闭为 `closed`。
8. 分派、转派、处理结果、退回、无需处理、关闭和敏感访问全部进入审计与时间线；`closed` 为终态，本期不支持重新打开。

### 8.6 权限变更与账号停用

1. 超级管理员进入账号或角色权限页面。
2. 选择账号、角色或权限点，查看当前权限和关联账号。
3. 修改角色、动作权限或数据范围。
4. 系统执行权限冲突、唯一超级管理员和高风险授权校验。
5. 管理员填写变更原因并确认。
6. 变更成功后立即生效，记录变更前后内容。
7. 账号停用后，其现有登录会话失效，后续登录被拒绝。
8. 变更失败时保持原权限不变，并记录失败原因。

### 8.7 敏感数据访问审计

1. 用户进入用户详情、反馈原文、AI 会话摘要或其他敏感页面。
2. 系统校验角色、页面权限和数据范围。
3. 系统获取访问原因，可由业务入口自动带入或要求用户填写。
4. 在展示敏感内容前写入访问日志。
5. 日志写入成功后展示脱敏或必要摘要；写入失败则拒绝展示。
6. 成功和失败访问均可在敏感数据访问日志中查询。

### 8.8 异常与回退规则

- 审核驳回：保留驳回原因，对象回到可编辑草稿流程。
- 发布失败：保持待发布或发布前状态，不覆盖线上版本。
- 下架失败：对象保持已发布，记录失败原因。
- 回滚失败：当前线上版本保持不变，记录失败原因。
- 权限变更失败：保持原权限不变，记录失败原因。
- 访问日志写入失败：不得展示敏感数据。
- 对象存在引用：下架、停用或回滚前展示关联对象和影响范围。

### 9.1 通用接口规范

| 类别 | 产品要求 |

| 身份认证 | 所有后台接口必须校验登录态；账号停用或锁定后现有会话失效 |

| 分页 | 列表接口支持页码、每页数量、总数；默认按更新时间倒序 |
| 搜索与筛选 | 支持关键词、状态、时间范围和模块特定筛选；无效筛选值返回明确提示 |
| 排序 | 仅允许指定字段排序，避免任意字段造成不稳定结果 |
| 数据返回 | 统一包含业务数据、当前权限、可执行操作、状态和必要的版本信息 |

| 幂等性 | 发布、下架、回滚、审核、停用和导出等高风险操作需避免重复提交造成重复结果 |
| 并发控制 | 编辑和发布对象需校验版本；数据已被他人更新时提示刷新，不直接覆盖 |

| 脱敏 | 用户联系方式、设备信息、精确登录信息和会话内容由服务端按角色返回脱敏结果 |
| 时间 | 请求与返回使用统一时间标准；页面按系统时区展示 |
| 导出 | 导出任务记录筛选条件、申请人、数据类型和结果；仅输出允许的聚合字段 |

## 10. 验收标准

### 10.1 全局功能验收

- 7 类固定角色均可创建测试账号并验证菜单、页面、按钮和数据范围。
- 无权限角色看不到菜单，直接访问页面也会被服务端拒绝。
- 列表页具备搜索、筛选、分页、加载、空、错误和无权限状态。
- 内容、题库、学习路径、AI 策略、写译题目和模考试卷均使用统一审核发布状态。
- 创建、编辑、提交审核、审核、发布、下架、回滚、停用、导出、权限变更和敏感访问均有日志。
- 已发布对象不允许直接覆盖修改，必须通过新版本进入审核发布流程。
- 审核驳回、下架、回滚、停用和权限变更必须填写原因。
- 发布失败、回滚失败和权限变更失败不会破坏原有有效状态。
- 用户联系方式、设备信息、反馈原文和 AI 会话按权限脱敏或摘要化。
- 用户级学习明细、反馈原文和完整 AI 会话不可批量导出。

### 10.2 模块验收标准

| 模块 | P0 验收场景 | 验收结果 |
| --- | --- | --- |
| 工作台 | 不同角色登录后看到不同待办；点击待办可进入有权限的目标页面 | 角色过滤正确，无越权数据，跳转正确 |
| 用户管理 | 客服搜索用户，查看诊断与任务状态，处理反馈并查看必要会话摘要 | 用户可定位；数据脱敏；访问和处理日志完整 |
| 题库与内容管理 | 教研创建题目和题组，内容运营创建每日一句与外刊，提交审核并发布 | 必填校验正确；状态完整；版本可追溯 |
| 学习路径配置 | 创建诊断规则和今日任务模板，绑定题组，校验后提交并发布 | 条件与输出可保存；引用有效；冲突有提示 |
| AI 陪练管理 | 创建 Prompt 和防依赖规则，发布版本，抽检会话并处理异常 | 高风险策略有审核；摘要访问留痕；异常可闭环 |
| 写译批改管理 | 创建写作与翻译题目，配置评分维度和反馈模板并发布 | 评分校验正确；题目与规则可关联；效果仅聚合展示 |
| 模考管理 | 创建试卷、配置分区题目分值和计时，审核发布并查看统计 | 分值与题目校验正确；版本发布成功；统计口径正确 |

| 权限与系统设置 | 创建账号、分配角色、调整权限、停用账号并查看日志 | 权限实时生效；唯一超管受保护；停用账号无法登录 |

### 10.4 数据与指标验收

- 新增用户：统计周期内首次注册的去重用户数。
- 活跃用户：统计周期内发生学习或 AI 陪练行为的去重用户数。
- Onboarding 完成率：完成 Onboarding 的用户数 ÷ 进入 Onboarding 的用户数。
- 诊断完成率：完成诊断的用户数 ÷ 开始诊断的用户数。
- 今日任务开始率：开始今日任务的用户数 ÷ 获得今日任务的用户数。
- 今日任务完成率：完成今日任务的用户数 ÷ 开始今日任务的用户数。
- 题目正确率：正确作答次数 ÷ 有效作答次数。
- 内容完成率：完成内容阅读或任务的人数 ÷ 开始人数。
- 写译二改率：发生二次修改的提交数 ÷ 写译提交数。
- 模考完成率：完成模考人数 ÷ 开始模考人数。
- AI 异常率：被标记异常的会话或回复数 ÷ 有效会话或回复数，分母需在页面口径说明中固定。
- 次日或 7 日留存：指定注册批次在对应日期仍活跃的用户数 ÷ 该批次新增用户数。

### 10.5 安全与审计验收

- 服务端必须执行权限校验，前端隐藏菜单不能作为唯一防线。
- 日志记录成功和失败操作，日志不得由普通业务角色修改或删除。
- 敏感数据展示前完成访问日志写入；写入失败时返回不可查看状态。
- 账号停用后，现有会话在合理时间内失效，后续请求返回登录或权限失效提示。
- 导出结果只包含允许字段，且记录申请人、筛选条件、时间和结果。
- 系统页面、日志和导出中不得出现密码、Token、模型密钥或其他认证凭据。

### 10.6 性能与兼容性验收

- 常规列表、详情、保存和筛选操作在正常网络下应有明确加载反馈，不出现无响应状态。
- 大列表必须分页，不一次性加载全部数据。
- 重复点击审核、发布、下架、回滚或停用不产生重复业务结果。
- 支持主流桌面浏览器的当前稳定版本，首版以桌面端 1280px 及以上宽度为主要使用场景。
- 页面发生接口失败时保留用户已填写但尚未提交的内容，并提供重试或返回入口。

### 10.7 MVP 上线判定

满足以下条件后，可判定 MVP 达到上线标准：

1. 10 个一级模块均有可访问页面或明确的 MVP 基础承接页面。
2. 7 类角色的权限和禁止范围全部通过验收。
3. 用户排查、内容管理、规则配置、AI 治理、审核发布、数据看板和权限审计七个核心闭环全部可运行。
4. 统一状态、版本和日志机制在所有发布对象中生效。
5. 不包含学校、教师、商业化、复杂 CRM、真人批改大系统或复杂实验平台等超出范围能力。
6. 无阻断业务闭环的 P0 缺陷；高风险权限与敏感数据相关缺陷必须清零。
