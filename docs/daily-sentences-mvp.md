# 每日一句运营闭环 MVP

日期：2026-07-12

## 目标

让内容运营能够完成每日一句从草稿、校验、审核、发布到效果回流的完整任务，并在需要时下架或复制新版本。

## 角色

| 角色 | 责任 |
| --- | --- |
| 内容运营 | 创建、编辑、预校验、提交审核、复制版本、查看效果 |
| 教研审核 | 审核、驳回、安排发布、发布和下架 |
| 超级管理员 | 全量操作和异常处理 |
| 数据分析、只读审计 | 查看聚合指标或操作记录 |
| Mock 调度器 | 到期发布、发布前复验和状态同步 |

## 主流程

创建草稿 → 校验内容、来源、配图和日期 → 提交审核 → 审核通过或驳回 → 立即/定时发布 → Mock 用户阅读/打卡 → 效果回流 → 下架或复制新版本。

## 业务约束

- 来源展示和来源凭证均为必填，不能只填写不可核验的出处文案。
- 配图必须引用有效 Mock 素材；素材失效会阻断提交或发布。
- 同一日期只能存在一个线上主内容；同一版本谱系的新版本可原子替换旧线上版本。
- 已发布内容不可直接编辑，只能复制为新草稿；历史用户事件不会复制。
- 定时发布使用 `Asia/Shanghai`，发布时间必须与内容日期一致且晚于当前时间。
- 未来日期不能立即发布；发布失败保持当前线上版本和待发布任务不变。
- 阅读事件按 `eventId` 幂等；打卡按用户、内容和版本去重。
- 下架内容不再接受新行为，但历史指标和操作记录保留。

## Mock 边界

- 不修改 Expo App，不接真实后端，不接真实文件上传。
- 配图来自内嵌 Mock 素材选择器，不包含素材管理 CRUD。
- 定时发布没有后台常驻进程，由每日一句、审核任务或运营数据请求触发到期检查。
- 内容效果来自后台 Mock 用户行为，不代表真实生产指标。
