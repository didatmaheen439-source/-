# 过级搭子 B 端后台管理系统组件规范

> 建议文件路径：`docs/admin-component-spec.md`  
> 文档版本：V1.0  
> 适用产品：过级搭子运营管理后台 MVP  
> 适用终端：桌面端中后台 Web 系统  
> 设计基线：Ant Design 企业级中后台设计语言与现有开源项目样式  
> 文档用途：作为 Codex 开发后台页面时的统一布局、组件、交互、状态和权限展示规范

---

## 0. 规范目标与使用原则

### 0.1 规范目标

本规范用于统一过级搭子 B 端后台的页面结构、组件选型、交互反馈和权限展示方式，避免不同模块由不同开发任务生成后出现布局、按钮、表格、弹窗和状态表达不一致的问题。

本规范适用于以下后台模块：

- 工作台；
- 用户管理；
- 题库与内容管理；
- 学习路径配置；
- AI 陪练管理；
- 写译批改管理；
- 模考管理；
- 运营数据；
- 审核发布；
- 权限与系统设置。

### 0.2 设计原则

1. **保持现有项目风格**：沿用当前开源项目已经使用的导航结构、主题色、字体、圆角、阴影、间距和 Ant Design 主题配置，不重新定义一套视觉系统。
2. **优先使用 Ant Design 原生组件**：存在合适的 Ant Design 组件时，不自制同类基础组件。
3. **不为统一而强制升级依赖**：以项目实际安装的 Ant Design 主版本和现有组件能力为准，避免仅为实现本规范新增不必要依赖。
4. **按需使用 ProComponents**：项目已经使用 ProLayout、PageContainer、ProTable 等组件时继续复用；项目未使用时，不要求为了本规范单独引入整套 ProComponents。
5. **统一优先于个性化**：MVP 阶段不为单个页面设计特殊交互，优先复用统一列表页、详情页、表单页和弹窗模式。
6. **业务状态优先于视觉装饰**：状态、风险、权限和操作结果必须清晰，不使用仅有装饰意义的渐变、复杂动效或大面积插画。
7. **可追踪优先**：审核、发布、下架、回滚、停用、权限变更和敏感数据访问必须明确操作入口、确认过程和反馈结果。
8. **服务端权限为准**：前端隐藏只用于改善体验，不能替代服务端权限校验。

### 0.3 推荐组件范围

| 使用场景 | 优先组件 |
| --- | --- |
| 页面骨架 | Layout、Menu、Breadcrumb、PageContainer（项目已使用时） |
| 页面标题与说明 | Typography、Space、Flex |
| 搜索与数据录入 | Form、Input、Select、DatePicker、InputNumber、Radio、Checkbox、Switch、Upload |
| 数据展示 | Table、Descriptions、Card、Tabs、Timeline、Statistic、Tooltip |
| 状态表达 | Tag、Badge、Alert、Result |
| 操作 | Button、Dropdown、Popconfirm、Modal、Drawer |
| 反馈 | Message、Notification、Alert、Result |
| 加载 | Spin、Skeleton |
| 空数据 | Empty |
| 分页 | Pagination 或 Table 内置分页 |

### 0.4 全局默认决策

| 事项 | 统一规则 |
| --- | --- |
| 搜索区每行字段数 | 宽屏每行最多 4 个字段；常规首行建议 3 个字段加按钮区；中等宽度 3 个字段；较窄桌面 2 个字段 |
| 列表默认页容量 | 20 条 |
| 表格默认排序 | 业务列表按更新时间倒序；日志列表按操作时间倒序 |
| 行内操作位置 | 表格最右侧固定“操作”列 |
| 行内直显操作数 | 最多 2 个，其他操作收进“更多” |
| 新增/编辑 | 字段与校验基本一致时复用同一个弹窗或表单 |
| 删除确认 | 所有删除均需二次确认；不可逆或高风险操作使用确认弹窗并说明影响 |
| 启用/停用展示 | 列表使用状态标签，不直接使用 Switch 作为行内快捷开关 |
| 表单必填提示 | 标签前显示必填标识，错误信息显示在字段下方，提交时定位首个错误项 |
| 空数据 | 使用 Empty；区分首次无数据、筛选无结果、无权限和接口错误 |
| 加载状态 | 列表局部使用 Table loading/Spin；详情首次加载使用 Skeleton；提交按钮使用 loading |
| 接口错误 | 不得伪装成空数据；按影响范围显示 Message、Alert 或 Result，并提供重试方式 |

## 1. 页面布局规范

### 1.1 后台整体布局

后台默认采用“顶部栏 + 左侧导航 + 主内容区”的中后台布局，保持现有开源项目的 Layout 和菜单样式。

- 左侧导航承载 10 个一级模块及其二级页面。
- 顶部栏承载系统名称、折叠菜单、当前账号、角色信息和退出入口。
- 主内容区承载面包屑、页面标题、页面说明、页面操作和业务内容。
- 不在同一项目中混用顶部一级导航和侧边一级导航两套主导航结构。
- 菜单折叠、菜单宽度和顶部栏高度沿用现有项目，不单独硬编码新的尺寸。

### 1.2 内容区结构

标准列表页从上到下固定为：

1. 面包屑；
2. 页面标题与页面级操作；
3. 页面说明或重要提示；
4. 搜索筛选区；
5. 列表操作工具栏；
6. 表格；
7. 分页。

标准详情页从上到下固定为：

1. 面包屑；
2. 页面标题、状态标签与详情级操作；
3. 页面说明或风险提示；
4. 基础信息；
5. 业务信息；
6. 版本、审核、发布或操作记录；
7. 关联数据。

标准表单页从上到下固定为：

1. 面包屑；
2. 页面标题与说明；
3. 表单分组；
4. 底部操作区。

### 1.3 内容宽度

- 列表页、表格页、数据看板默认使用内容区可用宽度，不设置过窄的最大宽度。
- 详情页和复杂表单页建议限制正文宽度，避免字段横向跨度过大；推荐最大内容宽度为 1200px 左右，并与项目现有容器规则保持一致。
- 弹窗、抽屉和表单内部不再嵌套多层 Card。
- 同一个视觉层级最多使用一层主 Card；必要的业务分组使用分区标题、Divider 或留白，不连续嵌套卡片。

### 1.4 间距

遵循 Ant Design 的 8px 基础节奏，并优先使用项目已有间距变量。

| 场景 | 建议间距 |
| --- | --- |
| 页面内容区外边距 | 24px；较窄桌面可降为 16px |
| 页面标题与说明 | 8px |
| 页面说明与首个内容区 | 16px |
| 搜索区与工具栏 | 16px |
| 工具栏与表格 | 12px 至 16px |
| 表单分组之间 | 24px |
| 同组字段之间 | 16px |
| 弹窗正文与底部按钮 | 使用组件默认间距，不额外压缩 |

### 1.5 响应式范围

- 后台以 1280px 及以上桌面宽度为主要设计目标。
- 需要兼容约 1024px 的较窄桌面视口，但不以手机端作为 MVP 验收范围。
- 视口变窄时优先减少搜索区每行字段数、允许表格横向滚动，不压缩到字段难以阅读。
- 表格列较多时，核心字段和操作列固定，非核心字段允许横向滚动。
- 不通过缩小字号来强行容纳更多内容。

### 1.6 页面背景与卡片

- 页面背景、Card 背景、边框、圆角和阴影完全沿用当前项目主题。
- 不新增渐变背景、玻璃拟态、强阴影或大圆角风格。
- 表格型页面优先使用一个包含筛选和表格的统一业务容器，或使用两个上下相邻的标准 Card；同一模块内必须保持一致。
- 页面中的 Alert、Empty、Result 等状态组件使用 Ant Design 默认视觉，不单独绘制复杂插画。

## 2. 页面标题规范

### 2.1 标题内容

- 页面标题使用明确的业务名词，例如“用户管理”“题库管理”“审核详情”“编辑诊断规则”。
- 列表页标题使用对象集合名称；详情页标题优先使用对象名称，无法使用对象名称时使用“对象类型 + 详情”。
- 新增页使用“新增 + 对象名称”；编辑页使用“编辑 + 对象名称”。
- 不使用“管理中心”“操作页面”“数据列表”等缺少业务含义的泛化标题。
- 标题原则上控制在一行内，避免在标题中堆叠状态、版本、ID 和说明。

### 2.2 标题层级

- 页面主标题仅出现一次，视觉层级沿用现有 PageContainer 或项目页面标题样式。
- Card 标题不得重复页面主标题。
- 页面内部一级分区标题使用统一的小标题样式，例如“基础信息”“规则配置”“版本记录”。
- 标题字号、字重和颜色不单独硬编码，复用项目 Typography 和主题 token。

### 2.3 标题区域布局

- 页面标题位于内容区左上方。
- 页面级操作位于标题区域右侧，右对齐。
- 详情页状态标签紧跟标题或位于标题下方的元信息区，不与操作按钮混排。
- 面包屑位于标题上方；项目已经通过 PageContainer 自动生成面包屑时，不重复手写。

### 2.4 标题区域操作

- 标题区域仅放页面级操作，例如“返回列表”“查看版本”“紧急回滚”。
- “新增”“导出”“刷新”等列表级操作默认放在表格工具栏，不在标题区重复出现。
- 同一个标题操作区最多有一个主按钮。
- 操作较多时，保留最重要的 1 至 2 个按钮，其他放入“更多”下拉菜单。

## 3. 页面说明规范

### 3.1 使用条件

页面说明只在以下场景展示：

- 页面业务目标不容易从标题直接理解；
- 页面包含敏感数据、审核发布或高风险配置；
- 页面需要解释数据口径、状态限制或操作后果；
- 页面首次使用需要简单说明。

普通列表页如标题已经清晰，可不重复增加说明。

### 3.2 文案规则

- 使用 1 至 2 句话说明“页面用于什么”和“操作时需要注意什么”。
- 单段建议不超过 80 个中文字符；复杂规则通过“查看说明”进入帮助内容，不在页面顶部堆积长文。
- 文案使用专业、准确、简洁的陈述句。
- 不使用“温馨提示”“亲”“请放心”等偏 C 端或客服化语言。
- 不重复标题，不罗列页面已有字段。

### 3.3 展示形式

| 场景 | 展示方式 |
| --- | --- |
| 普通页面说明 | 标题下方的次级文本 |
| 重要但非阻断提醒 | Alert，类型为 info 或 warning |
| 敏感数据访问提示 | Alert，说明访问将被记录 |
| 审核驳回、发布失败等持续状态 | Alert，展示原因和处理入口 |
| 指标口径 | 指标标题旁 Tooltip 或页面说明中的“指标说明”入口 |

### 3.4 禁止事项

- 不使用 Message 代替需要长期可见的页面说明。
- 不将重要风险只写在 Tooltip 中。
- 不在多个 Card 顶部重复同一段说明。

## 4. 搜索筛选区规范

### 4.1 基本结构

搜索筛选区由以下内容组成：

- 关键词搜索；
- 业务筛选字段；
- 时间范围；
- 查询、重置按钮；
- 展开/收起入口（筛选项较多时）。

筛选区默认置于表格上方，使用标准 Form 栅格排列，不使用弹窗承载常用筛选条件。

### 4.2 每行字段数量

这是后台统一的强制规则：

| 内容区宽度 | 每行最多字段数 | 推荐布局 |
| --- | --- | --- |
| 宽屏桌面，约 1440px 及以上 | 最多 4 个字段 | 首行通常为 3 个字段 + 右侧按钮区；展开后续行可放 4 个字段 |
| 常规桌面，约 1200px 至 1439px | 最多 3 个字段 | 2 至 3 个字段 + 按钮区 |
| 较窄桌面，约 1024px 至 1199px | 最多 2 个字段 | 2 个字段一行，按钮在行末或下一行右侧 |

补充规则：

- “字段数”按完整筛选控件计算，日期范围选择器计为 1 个字段。
- 查询和重置按钮不计入字段数量，但首行需要为按钮区预留足够宽度。
- 不允许为了塞入更多筛选项而将输入框压缩到难以输入。
- 默认收起状态优先显示 3 个最高频筛选字段；其余字段通过“展开”显示。
- 筛选字段超过 6 个时必须支持展开/收起，避免页面首屏被筛选区占满。

### 4.3 字段排序

搜索筛选字段按以下顺序排列：

1. 关键词；
2. 核心业务类型，例如考试类型、内容类型、题型；
3. 状态；
4. 归属人、创建人或处理人；
5. 时间范围；
6. 低频高级筛选项。

页面存在唯一高频查询条件时，将该字段放在第一位。例如用户管理优先用户 ID/昵称，审核发布优先对象名称/任务 ID。

### 4.4 关键词搜索

- 输入框占位文案明确可搜索内容，例如“请输入用户 ID 或昵称”。
- 自动去除输入内容首尾空格。
- 支持按 Enter 执行查询。
- 不默认在每次键入时自动调用接口，避免频繁请求和列表抖动。
- 关键词为空时允许查询全部数据。

### 4.5 查询与重置

- “查询”使用主按钮，位于按钮区最右侧或主要位置。
- “重置”使用默认按钮，位于查询按钮左侧。
- 重置应清空全部筛选项、关键词和排序条件，并返回第一页。
- 查询、重置、切换筛选项后均应返回第一页。
- 展开/收起是文本型次级操作，不使用主按钮。

### 4.6 筛选状态保留

- 从列表进入详情，再返回列表时，应保留关键词、筛选条件、分页和排序。
- 当前项目已经支持 URL 查询参数时，筛选状态优先同步到 URL。
- 当前项目未使用 URL 状态时，可保存在页面状态中，但同模块页面行为必须一致。
- 切换一级模块或主动重置后可清除列表状态。

### 4.7 看板筛选

- 数据看板筛选区可在条件变更后自动刷新，但必须显示局部加载状态。
- 看板中全局筛选放在页面顶部，各图表自身的局部筛选放在对应 Card 右上角。
- 全局与局部筛选不得使用同名字段表达不同口径。

## 5. 操作按钮区规范

### 5.1 操作区层级

后台存在三类操作区：

| 操作区 | 位置 | 适用操作 |
| --- | --- | --- |
| 页面级操作区 | 页面标题右侧 | 返回、查看全局版本、紧急回滚等页面级动作 |
| 列表工具栏 | 搜索区下方、表格上方 | 新增、导出、批量操作、刷新等列表级动作 |
| 行内操作区 | 表格最右侧“操作”列 | 查看、编辑、提交审核、处理、停用等单对象动作 |

同一动作只能出现在一个最合适的操作区，不重复放置。

### 5.2 列表工具栏布局

- 工具栏左侧显示数据总量摘要、已选数量或批量操作。
- 工具栏右侧显示业务操作，顺序建议为：次级操作、导出、刷新、主操作。
- “新增”通常为工具栏唯一主按钮，并位于最右侧。
- 无新增权限时，不展示新增按钮，不保留空位。
- 导出权限为 D；无导出权限时完全隐藏导出入口。
- 刷新可以使用图标按钮，但必须提供 Tooltip。
- 列设置、密度切换仅在当前项目已经提供此能力时保留，不为 MVP 单独增加。

### 5.3 批量操作

- 只有存在明确批量业务动作时才显示多选框。
- 用户选中数据后，工具栏显示“已选择 N 项”和可执行批量动作。
- 批量删除、停用、下架等危险操作必须显示影响数量并二次确认。
- 批量操作不得绕过单条操作的权限、状态和引用校验。
- 批量操作完成后清空已选项并刷新列表。

### 5.4 操作顺序

同一操作区内按以下顺序排列：

1. 查看类；
2. 编辑类；
3. 流程类，例如提交审核、审核、发布；
4. 状态变更类，例如启用、停用、下架、回滚；
5. 删除类。

危险操作始终放在最后，不与主按钮相邻造成误触。

## 6. 表格规范

### 6.1 使用原则

表格用于展示结构化数据以及需要搜索、筛选、排序、分页和操作的数据列表。普通信息展示不应为了统一而强制使用 Table，详情信息优先使用 Descriptions。

### 6.2 表格字段排序

所有业务表格按以下优先级排列字段：

1. 选择列或展开列，仅在需要时显示；
2. 核心标识字段，例如 ID、名称、标题；
3. 核心业务属性，例如考试类型、题型、分类、所属模块；
4. 关键结果或数量字段；
5. 状态字段；
6. 负责人、创建人、处理人；
7. 更新时间或操作时间；
8. 操作列。

具体规则：

- 名称或标题优先于 ID；ID 可作为名称下方辅助信息或独立窄列。
- 用户列表优先显示用户 ID、昵称、考试类型、学习状态和最近活跃。
- 审核列表优先显示对象名称、对象类型、提交人、提交时间、状态和优先级。
- 日志列表优先显示时间、操作者、动作、对象、结果和原因，默认按时间倒序。
- 运营数据聚合表优先显示维度名称、核心指标、对比值和更新时间。

### 6.3 核心列与固定列

- 核心名称列位于左侧；表格横向滚动时可固定在左侧。
- “操作”列始终位于表格最右侧，必要时固定在右侧。
- 操作列宽度根据操作数量统一设置，建议 160px 至 220px，不随内容无规则变化。
- 固定列数量应尽量少，避免左右固定区域占据大部分视口。
- 非核心字段可通过横向滚动查看，不允许压缩到内容不可读。

### 6.4 行内操作

- 操作列内最多直接展示 2 个高频操作。
- 超过 2 个操作时，保留“查看/详情”和最常用业务操作，其余放入“更多”下拉菜单。
- 危险操作放在“更多”菜单底部，或作为最后一个操作显示。
- 行内操作使用文本按钮或链接按钮，不使用多个实心按钮。
- 不依赖整行点击进入详情，避免与选择、复制和操作按钮冲突；通过名称链接或“详情”进入。
- 操作显示同时受角色权限和对象状态控制。

### 6.5 列内容格式

| 内容类型 | 展示规则 |
| --- | --- |
| 空值 | 统一显示“--”，数值 0 必须显示为 0 |
| 长文本 | 单行省略并通过 Tooltip 查看完整内容；摘要可最多显示 2 行 |
| ID | 等宽或普通文本均可，支持复制；不得使用过小字号 |
| 日期 | `YYYY-MM-DD` |
| 日期时间 | `YYYY-MM-DD HH:mm`，按系统配置时区展示 |
| 时长 | 根据业务展示为秒、分钟或“时:分:秒”，同一列口径一致 |
| 百分比 | 保留统一小数位，并明确分母口径 |
| 数值 | 默认右对齐；文本、状态左对齐 |
| 布尔值 | 使用“是/否”或明确状态标签，不使用空勾选框表达只读结果 |
| 状态 | 使用统一状态标签，不仅使用颜色点 |
| 敏感字段 | 脱敏显示；无权限时不返回真实数据 |

### 6.6 排序与筛选

- 默认只支持单列排序，MVP 不启用复杂多列排序。
- 业务列表默认按更新时间倒序。
- 日志、发布记录和登录记录默认按时间倒序。
- 计划发布列表可按计划发布时间升序或业务指定顺序。
- 大数据列表的排序和筛选由服务端完成。
- 支持排序的列必须显示清晰排序状态。
- 搜索或筛选变化后回到第一页。

### 6.7 表格密度与边框

- 普通业务列表使用项目默认或中等密度。
- 操作日志、访问日志等高密度页面可使用紧凑密度，但同一模块保持一致。
- 普通表格不使用完整纵向边框和斑马纹。
- 权限矩阵、字段对照或需要严格对应行列关系的表格可以使用带边框模式。
- 表头与正文保持清晰区分，但不新增高饱和底色。

### 6.8 滚动与表头

- 列数较多时允许横向滚动。
- 表格内容超过当前视口高度时，优先使用粘性表头或页面自然滚动。
- 不在一个页面中同时嵌套多个独立纵向滚动容器。
- 表格滚动后，操作列和核心名称列仍需可识别。

### 6.9 选择与展开

- 仅在存在批量操作时显示行选择框。
- 不允许选择当前无批量操作权限或状态不支持操作的数据；需要提供禁用原因。
- 展开行只用于展示少量补充信息，不承载完整详情页。
- 复杂记录、长文本、版本差异和关联列表应进入详情页或 Drawer。

### 6.10 加载、空和错误

- 表格加载时保留表头和原有布局，不让页面高度明显跳动。
- 首次无数据时在表格主体显示 Empty。
- 筛选无结果时显示“未找到符合条件的数据”，并提供重置筛选入口。
- 接口错误时显示错误状态和重试，不得显示为“暂无数据”。

## 7. 分页规范

### 7.1 位置

- 分页位于表格下方。
- 同一行左侧显示“共 N 条”，右侧显示分页控件。
- 使用 Table 内置分页时统一配置分页位置，不在表格外再增加第二套分页。

### 7.2 默认值

| 项目 | 默认规则 |
| --- | --- |
| 默认每页数量 | 20 条 |
| 可选每页数量 | 20、50、100 条 |
| 默认页码 | 第 1 页 |
| 页码变化 | 保留当前筛选和排序 |
| 筛选变化 | 回到第 1 页 |
| 排序变化 | 回到第 1 页 |

### 7.3 展示规则

- 总数超过一页时显示完整分页控件。
- 总数不超过一页时，可隐藏页码切换控件，但保留“共 N 条”的数据总量提示。
- 数据量较大时显示快速跳页能力。
- 不提供“全部展示”选项，避免一次性加载大量后台数据。
- 删除当前页最后一条数据后，如果当前页已无数据，应自动回到上一页。

### 7.4 服务端分页

- 业务列表统一使用服务端分页。
- 接口必须返回总数、当前页、每页数量和列表数据。
- 翻页请求期间保持当前表格结构，显示局部加载。
- 请求失败时保留当前页和筛选条件，允许用户重试。

## 8. 表单规范

### 8.1 表单布局

- 普通新增、编辑和配置表单默认使用标签在上、控件在下的垂直布局。
- 搜索筛选表单使用栅格化紧凑布局，不与业务编辑表单混用。
- 简单表单默认单列。
- 宽弹窗或完整页面中的短字段可使用双列布局。
- 长文本、富文本、规则表达、上传、题目内容和说明字段必须独占一行。
- 表单最多两列，不使用三列以上的高密度编辑布局。

### 8.2 字段顺序

表单字段按以下顺序组织：

1. 对象名称、标题或核心标识；
2. 适用范围和业务类型；
3. 核心配置；
4. 关联对象；
5. 状态或发布设置；
6. 备注与补充说明；
7. 系统只读字段。

复杂表单使用明确分组，例如：

- 基础信息；
- 内容配置；
- 规则条件；
- 关联题目/题组；
- 发布设置；
- 备注信息。

### 8.3 必填项提示

- 必填字段在标签前使用统一必填标识。
- 必填状态由真实校验规则产生，不手工在文案中写“必填”代替校验。
- 未填写必填项时，在对应字段下方显示明确错误文案，例如“请输入规则名称”。
- 提交表单后自动定位或滚动到第一个错误字段。
- 不只通过 Message 提示“请完善表单”，必须在具体字段上展示错误。
- 占位文案不能替代字段标签。

### 8.4 校验时机

- 必填、格式和长度校验在失焦或提交时触发。
- 关联字段变化后，相关字段应重新校验。
- 不在用户每输入一个字符时频繁显示错误，除非是即时格式校验或长度提示。
- 服务端返回的业务校验错误应定位到对应字段；无法定位时显示在表单顶部 Alert。

### 8.5 输入规范

- 状态、考试类型、题型、内容类型等枚举字段使用 Select、Radio 或 Checkbox，不允许自由输入。
- 数值使用 InputNumber，并设置合理上下限和单位。
- 时间范围使用日期或日期时间选择器，不使用纯文本输入。
- 长文本使用 TextArea，并显示合理字数限制。
- 文件使用 Upload，并展示文件类型、大小限制和失败原因。
- 所有文本输入保存前去除首尾空格；正文类内容保留必要换行。
- 系统生成字段，例如 ID、创建人、创建时间、版本号，使用只读展示，不伪装成可编辑输入框。

### 8.6 只读与禁用

- 用户可查看但不可修改的字段使用只读文本或 Descriptions。
- 只有在用户理解控件含义且当前状态暂时不可操作时才使用 disabled。
- 禁用控件必须通过 Tooltip、辅助文案或页面说明解释原因。
- 已发布对象的业务字段不得直接编辑；编辑时创建新草稿或新版本。

### 8.7 表单操作区

- 弹窗表单操作位于 Modal 底部右侧。
- 完整页面表单操作位于页面底部；长表单可使用吸底操作栏。
- 按钮顺序从左到右为：取消、保存草稿、主操作。
- 主操作根据业务使用“保存”“提交审核”“审核通过”等明确文案，不统一使用含义模糊的“确定”。
- 同一个操作区只有一个主按钮。
- 提交期间主按钮显示 loading，相关提交按钮禁用，防止重复提交。

### 8.8 未保存提醒

- 用户修改表单后关闭弹窗、切换路由或返回列表时，需要提示“当前修改尚未保存，确认离开吗？”
- 表单未发生变化时直接关闭，不弹确认。
- 保存成功后清除未保存状态。

## 9. 新增 / 编辑弹窗规范

### 9.1 是否复用同一个弹窗

新增和编辑默认复用同一个弹窗及同一套表单结构，适用条件如下：

- 字段结构基本一致；
- 校验规则基本一致；
- 提交后的业务状态一致；
- 权限差异仅影响个别字段是否可编辑；
- 编辑时只需加载初始值和对象 ID。

以下情况不强制复用：

- 新增和编辑的业务流程明显不同；
- 超过约三分之一字段或操作不同；
- 编辑已发布对象需要走新版本、版本对比或影响确认；
- 表单过长，需要独立页面承载；
- 编辑涉及复杂编排、拖拽、预览或多步骤流程。

即使不复用整个弹窗，也应复用字段分组、校验规则和基础表单组件，避免两套规则漂移。

### 9.2 弹窗标题

- 新增模式：`新增 + 对象名称`。
- 编辑模式：`编辑 + 对象名称`。
- 查看模式不复用编辑标题，使用“查看详情”或对象名称。
- 标题不放状态和版本信息；状态与版本放在正文元信息区域。

### 9.3 弹窗宽度

| 复杂度 | 建议宽度 | 适用范围 |
| --- | --- | --- |
| 简单 | 520px 左右 | 约 1 至 8 个普通字段 |
| 中等 | 720px 左右 | 约 9 至 16 个字段或双列短字段 |
| 较复杂 | 880px 至 960px | 含较多说明、关联选择或预览，但仍可一次完成 |
| 复杂流程 | 不使用 Modal | 使用独立页面或 Drawer |

宽度优先沿用项目已有 Modal 尺寸体系，不为单个页面任意设置特殊宽度。

### 9.4 弹窗内容

- 默认垂直表单布局。
- 简单字段单列，短字段可双列。
- 不在 Modal 中再次打开 Modal。
- 需要选择大量关联对象时，可使用独立选择 Drawer 或跳转选择页，但不形成多层遮罩。
- 弹窗正文过长时允许正文内部滚动，标题和底部操作保持可见。

### 9.5 弹窗底部按钮

- 右侧依次为“取消”和主操作按钮。
- 普通新增/编辑主操作使用“保存”。
- 需要直接进入审核流程时，可使用“提交审核”，并将“保存草稿”作为次级按钮。
- 主按钮提交时显示 loading，并防止重复提交。
- 保存失败时弹窗保持打开，保留用户输入。

### 9.6 关闭行为

- 点击取消、关闭图标或遮罩时，若表单已修改，必须确认是否放弃修改。
- 存在高价值长表单时，不建议允许点击遮罩直接关闭。
- 保存成功后关闭弹窗，刷新列表并保留当前筛选、分页和排序。
- 编辑成功后列表对应行应展示最新数据，不要求跳回第一页。
- 新增成功后可回到第一页或在当前排序下刷新，行为在同一模块内保持一致。

## 10. 详情页规范

### 10.1 页面结构

详情页采用以下统一结构：

1. 面包屑；
2. 标题、状态、版本和页面级操作；
3. 页面说明、敏感访问提示或风险 Alert；
4. 基础信息；
5. 核心业务信息；
6. 关联对象；
7. 审核、发布、版本和操作记录。

### 10.2 标题与操作

- 标题优先展示对象名称。
- 状态标签紧跟标题或位于标题下方元信息区。
- 对象 ID、版本号、创建时间等使用次级文本展示。
- 操作位于右上角，根据权限和状态显示“编辑”“提交审核”“审核”“发布”“下架”“回滚”等。
- 直显操作不超过 2 个，其余进入“更多”。
- 危险操作位于最后，并遵循确认规范。

### 10.3 信息展示

- 基础字段优先使用 Descriptions，不使用禁用表单模拟详情。
- 普通详情默认双列展示。
- 宽屏下短字段可三列，但同一分组必须保持统一。
- 长文本、题干、解析、Prompt、规则内容和备注独占整行。
- 空值统一显示“--”。
- ID、版本号等支持复制。
- 状态、风险等级和处理结果使用统一 Tag。

### 10.4 分组与标签页

- 一个页面信息量较小时使用纵向分组。
- 存在学习记录、反馈记录、版本记录、操作日志等独立数据集时使用 Tabs。
- Tabs 数量建议不超过 5 个；更多内容应重新分组或进入独立页面。
- 切换 Tab 不改变对象上下文，标题和页面级操作保持不变。
- 记录类 Tab 使用表格，并遵循统一表格和分页规范。

### 10.5 敏感数据

- 联系方式、设备信息、AI 会话摘要、反馈原文等敏感字段默认脱敏或摘要化。
- 无查看权限时不展示字段值，也不提供前端解密能力。
- 允许查看敏感内容时，应在内容展示前完成权限校验和访问日志写入。
- 访问日志写入失败时，不得展示敏感内容。
- 需要主动查看完整内容时，使用明确的“查看敏感信息”操作，并提示访问将被记录。

### 10.6 返回行为

- 从列表进入详情后返回，应恢复原列表的筛选、分页和排序。
- 面包屑和返回按钮均返回正确上级页面。
- 不使用浏览器历史作为唯一返回方式。

## 11. 状态标签规范

### 11.1 总体规则

- 所有业务状态统一使用 Tag 或 Badge + 文案展示。
- 状态不能只靠颜色区分，必须显示完整中文文案。
- 同一状态在所有模块使用同一颜色语义。
- 不允许各页面自行创建“处理中”“进行中”“执行中”等同义状态。
- 默认使用 Ant Design 语义色或项目主题映射，不硬编码一套新色板。
- 未识别状态显示灰色“未知”，并记录异常，不显示空白。

### 11.2 审核发布状态

| 状态 | 语义色 | 展示说明 |
| --- | --- | --- |
| 草稿 | 默认灰 | 尚未提交审核，可编辑 |
| 待审核 | 处理中蓝 | 已提交，等待审核 |
| 已驳回 | 错误红 | 审核未通过，需要修改 |
| 已通过 | 成功绿 | 审核已通过，尚未发布 |
| 待发布 | 警告橙 | 已具备上线条件，等待发布 |
| 已发布 | 成功绿 | 当前线上生效 |
| 已下架 | 默认灰 | 已从线上移除 |
| 已回滚 | 紫色或项目辅助色 | 当前版本已回退至历史版本 |

“已通过”和“已发布”都可使用成功语义色，但必须通过文案明确区分。

### 11.3 用户反馈状态

| 状态 | 语义色 |
| --- | --- |
| 待处理 | 警告橙 |
| 处理中 | 处理中蓝 |
| 已处理 | 成功绿 |
| 无需处理 | 默认灰 |
| 关闭 | 默认灰 |

### 11.4 账号与配置状态

| 状态 | 语义色 | 规则 |
| --- | --- | --- |
| 启用 | 成功绿 | 表示当前可用 |
| 停用 | 默认灰 | 表示人为停止使用 |
| 锁定 | 错误红 | 表示安全或登录风险限制 |
| 异常 | 错误红或警告橙 | 根据风险等级区分 |

### 11.5 启用 / 停用展示

- 列表中使用“启用”“停用”状态标签。
- 不在列表中直接放置 Switch 作为快捷开关，避免误触和绕过原因填写、引用校验或审计。
- 需要修改状态时，通过行内“启用”或“停用”操作触发确认。
- 表单中的初始配置可以使用 Switch，但保存或切换高风险状态时仍需执行对应业务校验。
- “停用”不等同于“删除”；停用数据仍需保留历史记录和引用关系。

### 11.6 风险与优先级

- 风险等级和业务状态分开显示，不合并为一个标签。
- 高风险使用红色，中风险使用橙色，低风险使用默认或蓝色。
- 优先级使用“高 / 中 / 低”或“P0 / P1 / P2”中的一种，不在同一系统中混用。

## 12. 按钮规范

### 12.1 按钮层级

| 类型 | 使用场景 |
| --- | --- |
| 主按钮 | 当前操作区唯一最重要动作，例如新增、查询、保存、提交审核 |
| 默认按钮 | 取消、重置、保存草稿、导出等次级动作 |
| 文本/链接按钮 | 表格行内查看、编辑、跳转、展开等轻量动作 |
| 危险按钮 | 删除、下架、回滚、停用账号、修改高风险权限等 |

### 12.2 主按钮数量

- 一个操作区域只能有一个主按钮。
- 页面标题区、列表工具栏、弹窗底部和表单底部视为不同操作区域，但不能重复同一主操作。
- 不将“保存”和“提交审核”同时设置为主按钮；推荐“提交审核”为主按钮，“保存草稿”为默认按钮。

### 12.3 按钮位置

- 页面级按钮位于页面标题右侧。
- 列表级按钮位于表格工具栏右侧。
- 表单和弹窗按钮位于底部右侧。
- 表格行内按钮位于最右侧操作列。
- 危险操作位于同组操作的最后。

### 12.4 按钮文案

- 使用“动词 + 对象”或明确动词，例如“新增题目”“提交审核”“查看详情”“停用账号”。
- 上下文已经明确对象时，可使用“新增”“编辑”“保存”。
- 不使用含义模糊的“操作”“处理”“确定”，确认弹窗的确认按钮应说明动作，例如“确认下架”。
- 删除确认按钮使用“确认删除”，不使用普通“确定”。

### 12.5 图标

- 新增、导出、刷新等常见按钮可使用图标配合文字。
- 除刷新、关闭、展开等通用动作外，不单独使用无文字图标。
- 图标按钮必须提供 Tooltip 和可访问名称。
- 同一动作在不同页面使用同一图标。

### 12.6 禁用与加载

- 用户无权限时隐藏按钮，不使用 disabled 暗示存在不可获得的权限。
- 用户有权限但当前对象状态不允许操作时，按钮可禁用，并解释原因。
- 提交异步操作时按钮显示 loading，并禁用重复点击。
- 加载完成后恢复按钮状态；失败时保留原页面数据和用户输入。

### 12.7 行内操作数量

- 行内最多直显 2 个操作。
- 超过 2 个时使用“更多”。
- “查看”或对象名称链接作为第一入口。
- “编辑”作为第二高频入口。
- 删除、停用、下架、回滚等放在最后。

## 13. 删除确认规范

### 13.1 是否需要二次确认

所有删除操作均必须二次确认。这里的二次确认是指：用户点击删除后，系统再次明确询问并由用户确认，不能直接执行删除。

- 单条普通草稿删除可使用 Popconfirm。
- 批量删除、存在引用的对象、账号删除、权限相关删除或影响范围较大的操作使用 Modal。
- 不使用浏览器原生确认框。

### 13.2 删除与其他状态操作的区别

- 删除：数据不可恢复或从业务层彻底移除，仅适用于未发布、未被引用的草稿或临时数据。
- 停用：保留数据和历史关系，但不再用于新业务。
- 下架：将当前线上内容移除，保留发布版本和记录。
- 回滚：恢复历史版本，保留问题版本记录。

MVP 优先使用停用、下架和回滚，减少物理删除。

### 13.3 确认内容

确认区域至少包含：

- 操作对象名称；
- 操作后果；
- 是否可恢复；
- 关联影响或影响数量；
- 确认和取消按钮。

推荐文案：

- 标题：“确认删除该题目？”
- 说明：“删除后不可恢复，且不会保留该草稿的编辑内容。”
- 确认按钮：“确认删除”
- 取消按钮：“取消”

### 13.4 高风险确认

以下操作虽然不一定是删除，也必须使用高风险确认 Modal：

- 发布；
- 下架；
- 回滚；
- 停用账号；
- 角色权限变更；
- 批量停用；
- 删除或停用被其他对象引用的数据。

高风险确认需要展示影响范围，并按 PRD 要求填写操作原因。原因未填写时不能提交。

### 13.5 提交与结果

- 确认按钮使用危险样式。
- 提交期间显示 loading，禁止重复操作。
- 操作成功后关闭确认框、刷新列表并显示明确成功提示。
- 操作失败时保留确认框或返回原页面，显示失败原因；不得先从列表移除再静默恢复。

## 14. 成功提示规范

### 14.1 轻量成功提示

新增、编辑、保存草稿、更新状态、添加备注等即时完成的操作，使用 Message 成功提示。

- 提示位于页面顶部居中并自动消失。
- 文案必须说明具体结果，例如“题目保存成功”“反馈已标记为已处理”。
- 不使用泛化的“操作成功”。
- 同一次操作只显示一次成功反馈，不同时弹出 Message 和 Notification。

### 14.2 成功后的页面行为

| 操作 | 成功后行为 |
| --- | --- |
| 新增 | 关闭弹窗，刷新列表；按模块规则返回第一页或保持当前排序 |
| 编辑 | 关闭弹窗，刷新当前页并保留筛选条件 |
| 保存草稿 | 保留当前页面或关闭弹窗，明确显示草稿状态 |
| 提交审核 | 刷新对象状态为“待审核”，移除不再可用的编辑操作 |
| 删除 | 刷新列表；当前页无数据时返回上一页 |
| 启用/停用 | 刷新状态标签和可执行操作 |
| 发布/下架/回滚 | 刷新版本、状态和操作记录 |

### 14.3 重要流程成功

- 发布、回滚、批量任务、导出任务等重要操作可使用 Notification 或 Result，但不阻断用户继续浏览。
- 需要展示版本号、影响范围或后续入口时，使用成功 Modal 或 Result。
- 异步导出只提示“导出任务已创建”，完成结果通过任务入口或通知反馈，不长时间阻塞当前页面。

### 14.4 成功文案

成功文案使用已完成时态：

- “保存成功”；
- “已提交审核”；
- “发布成功，当前生效版本为 V1.3”；
- “账号已停用”；
- “已创建导出任务”。

避免使用：

- “恭喜你”；
- “太棒了”；
- “操作完成啦”；
- 与中后台业务无关的情绪化表达。

## 15. 错误提示规范

### 15.1 错误分级

| 错误范围 | 展示方式 | 示例 |
| --- | --- | --- |
| 单字段输入错误 | 字段下方校验文案 | 名称为空、格式错误、超出长度 |
| 表单级业务错误 | 表单顶部 Alert + 对应字段错误 | 规则冲突、权重合计不正确 |
| 单次操作失败 | Message.error | 保存失败、更新备注失败 |
| 需要处理的复杂失败 | Modal 或 Notification | 发布失败、回滚失败、批量任务部分失败 |
| 页面局部接口失败 | 局部 Alert/错误占位 + 重试 | 表格、图表、关联记录加载失败 |
| 整页不可用 | Result error/403/404/500 | 无权限、对象不存在、系统异常 |

### 15.2 接口错误时如何展示

接口错误必须与空数据明确区分：

- 列表首次加载失败：在表格区域展示错误状态、简要原因和“重新加载”按钮，不显示“暂无数据”。
- 列表刷新失败：保留原有数据和筛选条件，在表格上方或局部显示失败提示。
- 详情加载失败：使用 Result 或页面级 Alert，提供返回列表和重试入口。
- 表单提交失败：保持弹窗或表单打开，保留用户输入，在字段或表单顶部展示错误。
- 局部卡片失败：只替换失败卡片内容，不让整页不可用。
- 敏感访问日志写入失败：显示错误并拒绝展示敏感数据。

### 15.3 常见状态处理

| 状态 | 页面处理 |
| --- | --- |
| 未登录或登录失效 | 提示登录状态失效并进入登录流程 |
| 403 无权限 | Result 403，提供返回首页或上一页入口 |
| 404 对象不存在 | Result 404，说明对象可能已删除或无权访问 |
| 409 状态或版本冲突 | Modal 或 Alert，提示数据已被他人更新，要求刷新后重新操作 |
| 422 业务校验失败 | 定位到字段或在表单顶部展示具体规则 |
| 500 系统错误 | Result/Alert，提供重试；必要时展示可供排查的请求编号 |

### 15.4 错误文案

错误提示需要包含：

- 发生了什么；
- 用户能做什么；
- 必要时提供请求编号或错误编号。

示例：

- “保存失败，规则优先级与现有配置冲突，请调整后重试。”
- “发布失败，线上版本未发生变化。请稍后重试或联系管理员。”
- “数据已被其他用户更新，请刷新页面后重新编辑。”

不得向用户展示：

- 技术堆栈；
- 数据库报错；
- 未处理的英文异常；
- 密钥、接口地址或其他敏感技术信息。

### 15.5 重试规则

- 只读查询失败可提供“重新加载”。
- 保存、发布、回滚等操作在重试前必须确认上一次请求结果，避免重复提交。
- 高风险接口必须具备幂等能力；前端按钮 loading 不能作为唯一防重复措施。

## 16. 加载状态规范

### 16.1 加载类型

| 场景 | 加载方式 |
| --- | --- |
| 表格首次加载或翻页 | Table loading 或表格区域 Spin |
| 表格刷新 | 保留原数据，表格区域显示 loading |
| 详情页首次加载 | Skeleton |
| 卡片或图表加载 | 卡片内部 Spin 或 Skeleton |
| 按钮提交 | 按钮 loading |
| 页面路由切换 | 页面内容 Skeleton 或居中 Spin，沿用项目现有方案 |
| 异步导出、发布任务 | 创建任务后解除页面阻塞，通过任务状态反馈 |

### 16.2 显示时机

- 极短请求可延迟约 300ms 显示 loading，避免快速闪烁。
- 超过约 1 秒的加载应显示明确加载状态。
- 加载时间较长时显示“正在加载…”或具体任务说明。
- 不在同一区域同时显示 Skeleton 和 Spin。

### 16.3 表格加载

- 保留表头、列宽和分页区域，避免页面跳动。
- 翻页和筛选时可保留旧数据并覆盖 loading，但加载期间不得允许对旧数据执行高风险操作。
- 加载完成后更新数据和总数。
- 请求失败时停止 loading，转为错误状态。

### 16.4 Skeleton 使用

- Skeleton 仅用于详情、卡片、图文内容等首次加载。
- 已经加载过数据后的刷新不再切换回 Skeleton，改用局部 loading。
- Skeleton 结构应大致匹配真实内容，避免完成加载后布局大幅变化。

### 16.5 提交加载

- 点击保存、审核、发布、下架、回滚、删除等操作后，确认按钮或主按钮显示 loading。
- loading 期间禁用同一操作的重复触发入口。
- 不冻结整个页面，除非操作本身必须阻断其他操作。
- 请求失败后恢复按钮，并保留用户当前输入与页面上下文。

### 16.6 长任务

- 导出、大批量处理等长任务不使用无限旋转的 Modal 阻塞用户。
- 提交后返回任务 ID 或任务状态，并提示“任务已创建”。
- 任务状态至少包含处理中、成功、失败。
- 失败任务提供失败原因或重新发起入口。

## 17. 空状态规范

### 17.1 空状态分类

空状态必须区分以下情况：

| 类型 | 文案 | 操作 |
| --- | --- | --- |
| 初始无数据 | “暂无题目”或“暂无反馈记录” | 有创建权限时显示“新增题目”等主操作 |
| 筛选无结果 | “未找到符合条件的数据” | 显示“重置筛选” |
| 关联数据为空 | “暂无关联版本” | 可提供关联或前往配置入口 |
| 看板无数据 | “当前时间范围内暂无数据” | 提示调整时间范围 |
| 无权限 | 不使用 Empty | 使用 Result 403 |
| 接口错误 | 不使用 Empty | 使用错误状态和重试 |

### 17.2 页面展示

- 表格空数据时，在表格主体区域居中展示 Empty。
- 卡片无数据时，在卡片内容区展示紧凑 Empty，不改变 Card 标题和筛选。
- 整页无数据时，Empty 位于主内容区视觉中心，但保留页面标题和说明。
- 不用空白页面表达无数据。

### 17.3 引导操作

- 用户拥有创建权限时，首次无数据可提供一个主按钮。
- 用户无创建权限时，只展示说明，不显示不可用按钮。
- 筛选无结果时优先提供“重置筛选”，不提供“新增”造成误导。
- 被权限限制导致数据为空时，服务端应返回明确权限结果，不伪装成业务无数据。

### 17.4 视觉规范

- 使用 Ant Design Empty 默认图形或项目现有空状态资源。
- 不为每种空数据制作复杂插画。
- 文案保持一行主说明，可增加一行简短辅助说明。
- 空状态操作数量不超过 2 个。

## 18. 权限控制展示规范

### 18.1 权限层级

后台权限必须同时覆盖以下四个层级：

1. 菜单权限；
2. 页面权限；
3. 操作权限；
4. 数据范围权限。

前端显示和后端接口必须使用一致的权限结果。

### 18.2 菜单权限

- 用户没有一级模块权限时，不展示该一级菜单。
- 用户可访问模块但无某二级页面权限时，不展示对应二级菜单。
- 菜单隐藏不代表已经完成安全控制，直接访问路由仍需校验。
- 当前角色没有任何可访问子页面时，不展示空父菜单。

### 18.3 页面权限

- 直接访问无权限页面时显示 Result 403。
- 403 页面提供“返回首页”或“返回上一页”入口。
- 不显示空白页、不自动跳转到不相关页面，也不使用“暂无数据”代替无权限。
- 只读审计角色可以查看授权页面，但不展示新增、编辑、审核、发布、删除和导出操作。

### 18.4 按钮权限

- 用户无该动作权限时，隐藏按钮。
- 用户有权限但当前状态不允许操作时，显示禁用按钮，并解释原因。
- 行内操作由“角色权限 + 数据范围 + 对象状态”共同决定。
- 同一对象的可执行操作优先使用接口返回的可操作列表作为前端展示依据。
- 不允许只在前端根据角色名称硬编码全部权限逻辑。

### 18.5 数据范围权限

- 数据范围由服务端过滤，前端不能获取后再隐藏无权数据。
- 数据分析角色只接收聚合或脱敏数据。
- 客服只能查看排查所需的单用户数据。
- 内容、教研、AI 角色只接收自己业务范围内的反馈和数据。
- 无导出权限时接口也必须拒绝导出请求。

### 18.6 敏感字段权限

- 敏感字段默认脱敏，例如联系方式、设备信息、AI 会话摘要和反馈原文。
- 无查看权限时不返回完整字段值。
- 有查看权限时仍应根据 PRD 记录访问人、对象、来源页面、访问原因、时间和结果。
- 敏感访问日志写入成功后才能展示内容。
- 复制、导出和查看完整内容应分别校验权限，不因具有查看权限而自动获得导出权限。

### 18.7 状态导致的操作限制

以下情况使用禁用或隐藏，不属于角色权限不足：

- 已发布内容不能直接编辑；
- 待审核对象不能再次提交审核；
- 未审核通过对象不能发布；
- 被引用对象不能直接删除；
- 唯一超级管理员不能被停用；
- 已关闭反馈不能继续修改处理状态。

页面需要向用户说明限制原因，并提供合法的下一步操作，例如“创建新版本”“先撤回审核”“查看引用关系”。

### 18.8 接口权限错误

- 前端预判有权限但接口返回 403 时，以接口结果为准。
- 页面级请求返回 403 时显示无权限页面。
- 单个按钮操作返回 403 时显示“当前账号无此操作权限，请刷新页面或联系管理员”。
- 权限被管理员实时收回后，刷新权限状态并移除相关入口。
- 账号停用或锁定后，当前会话失效并进入登录流程。

## 19. 页面模板落地规范

### 19.1 标准列表页模板

一个标准后台列表页应包含：

- 页面标题；
- 可选页面说明；
- 搜索筛选区；
- 列表工具栏；
- 表格；
- 分页；
- 新增/编辑弹窗；
- 删除或高风险操作确认；
- 加载、空、错误和无权限状态。

Codex 生成列表页时不得省略以下状态：

- 首次加载；
- 查询中；
- 空数据；
- 筛选无结果；
- 接口失败；
- 无权限；
- 操作提交中；
- 操作成功；
- 操作失败。

### 19.2 标准详情页模板

一个标准详情页应包含：

- 标题、状态和版本；
- 详情级操作；
- 基础信息；
- 业务信息；
- 创建人、创建时间、更新人、更新时间；
- 审核、发布或操作记录；
- 敏感数据访问控制；
- 返回列表并恢复列表状态。

### 19.3 标准表单页模板

一个标准表单页应包含：

- 表单标题和说明；
- 明确字段分组；
- 必填标识和字段级校验；
- 服务端校验错误展示；
- 保存草稿或主提交操作；
- 提交 loading；
- 未保存离开确认；
- 成功与失败反馈。

### 19.4 标准审核页模板

审核页应包含：

- 对象基础信息；
- 当前版本和变更摘要；
- 版本差异；
- 引用关系与影响范围；
- 审核历史；
- “审核通过”和“驳回”操作；
- 驳回原因必填；
- 操作提交 loading；
- 审核结果反馈。

### 19.5 标准日志页模板

日志页应包含：

- 操作者、角色、动作、对象、结果和时间筛选；
- 默认按时间倒序；
- 只读表格；
- 日志详情；
- 敏感字段脱敏；
- 无编辑、删除和批量修改入口；
- 导出入口仅在 PRD 明确授权时显示。

## 20. Codex 开发约束与验收清单

### 20.1 开发约束

- 不重新实现 Button、Table、Modal、Form、Tag、Empty、Spin、Skeleton 等基础组件。
- 可以封装轻量业务组件以统一行为，例如页面容器、搜索区、状态标签、权限判断和确认操作，但封装不得改变 Ant Design 基础交互语义。
- 不为单个页面新增全局主题变量。
- 不在 JSX 或页面样式中散落同一状态的多套颜色。
- 不把权限判断仅写在按钮点击事件中。
- 不把接口失败统一处理成空数组。
- 不因使用 Mock 数据而省略 loading、error、empty 和 permission 状态。
- 不自动生成未在 PRD 中定义的新状态、新角色或复杂批量流程。

### 20.2 页面交付验收

每个页面提交前至少检查：

| 检查项 | 验收标准 |
| --- | --- |
| 布局 | 符合对应列表、详情、表单或审核模板 |
| 标题 | 业务名称准确，没有重复标题 |
| 搜索区 | 每行字段数量符合规范，支持查询和重置 |
| 表格 | 字段顺序正确，操作列在最右侧，空值格式统一 |
| 分页 | 默认 20 条，筛选后回第一页，返回详情前状态可恢复 |
| 表单 | 必填项有标识，错误在字段下方，提交可定位首个错误 |
| 新增/编辑 | 能复用时复用同一弹窗，关闭未保存内容有确认 |
| 状态 | 使用统一状态标签和语义色 |
| 删除 | 有二次确认，说明不可恢复和影响范围 |
| 成功 | 反馈具体，不重复弹出多个提示 |
| 错误 | 不伪装成空数据，提供明确原因和重试方式 |
| 加载 | 列表、详情和提交均有合适 loading |
| 空状态 | 区分初始无数据、筛选无结果、无权限和接口错误 |
| 权限 | 菜单、页面、按钮和数据范围同时生效 |
| 敏感数据 | 按权限脱敏，查看前完成访问审计 |
| 高风险操作 | 原因必填，操作有 loading，结果可追踪 |

### 20.3 一致性验收

- 相同对象在列表、详情、弹窗和审核页使用相同字段名称。
- 相同状态在所有模块使用相同文案与颜色语义。
- 相同操作使用相同按钮文案、位置和确认方式。
- 相同接口错误在同类页面使用相同反馈层级。
- 相同角色在不同页面的权限边界与 PRD 权限矩阵一致。
- 页面风格与当前开源项目保持一致，不出现独立于项目的特殊视觉体系。
